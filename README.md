# بهجة — تطبيق الموبايل (Flutter)

تطبيق واحد لكل أدوار منصة **بهجة** لإدارة الحضانات: وليّ الأمر، والمعلمة، والإدارة. يتصل بواجهة الـ API (`/api/v1`) في مستودع الخادم [`bahja`](https://github.com/Melfarghaly/bahja).

الواجهة عربية من اليمين لليسار افتراضياً، مع دعم الإنجليزية. الشاشات تُبنى من صلاحيات المستخدم في الحضانة (`capabilities` في `GET /v1/me`)، فالمعلمة التي هي أيضاً أم ترى العالمين معاً.

## ما يقدمه التطبيق

| الدور | الشاشات |
|---|---|
| **الجميع** | الدخول بكلمة المرور أو برمز SMS، اختيار الحضانة، صندوق الإشعارات، اللغة، تسجيل الخروج |
| **وليّ الأمر** | أطفالي وحالة اليوم، سجل الحضور، يوميات الطفل (صور ووجبات ونوم...) مع الإقرار بالحوادث، كود الاستلام المتغيّر (QR يتجدد كل 30 ثانية)، تصاريح الاستلام لمرة واحدة، إعدادات الإشعارات وإذن التصوير، الفواتير والدفع (Paymob أو كود فوري) |
| **المعلمة** | كشف الحضور اليومي (تسجيل حضور، تسليم مع اختيار مستلم مخوَّل، تنبيه التأخر)، مسح كود الاستلام عند الباب (أخضر / أحمر)، نشر تحديثات الحائط بالأنواع لطفل أو لفصل مع الصور، حائط الحضانة |
| **الإدارة** | كل ما سبق + الاشتراك والاستهلاك |

## التشغيل

```bash
flutter pub get

# على محاكي أندرويد مع خادم Laravel محلي (php artisan serve):
flutter run

# على خادم آخر:
flutter run --dart-define=API_BASE_URL=https://app.example.com/api
```

- **عنوان الخادم الافتراضي:** `http://10.0.2.2:8000/api` على محاكي أندرويد (هو جهازك المضيف)، و`http://localhost:8000/api` في غير ذلك.
- **حسابات البيانات التجريبية** (`php artisan migrate:fresh --seed` في الخادم)، وكلمة المرور `password` لها كلها:
  - المالكة: `owner@bahga.test`
  - المعلمة: `teacher@bahga.test`
  - وليّة الأمر: `01000000002`
- **إصدار الإنتاج:** `flutter build apk --dart-define=API_BASE_URL=...`. نسخة الإنتاج لا تسمح بـ HTTP غير المشفّر، والسماح به مقصور على نسخة التطوير.

## البنية

```
lib/
├── app/          # MaterialApp، المسارات (go_router)، الحالة العامة (Riverpod): الجلسة واللغة
├── core/
│   ├── config/   # Env: عنوان الخادم ورقم الإصدار (--dart-define)
│   ├── models/   # نماذج مبنية على استجابات الـ API الحقيقية
│   ├── network/  # ApiClient (Dio) + ApiException للخطأ الموحّد {message, code, errors}
│   ├── storage/  # SessionStore: التوكن والحضانة في Keychain/Keystore
│   ├── theme/    # ألوان بهجة وخط Tajawal (مضمَّن)
│   └── utils/
├── data/         # Repositories: طبقة واحدة لكل مجموعة endpoints
├── features/     # الشاشات حسب المجال: auth, guardian, wall, staff, billing, notifications, account
├── l10n/         # نصوص الواجهة (عربي/إنجليزي)
└── shared/       # مكوّنات مشتركة (حالات التحميل والخطأ، القوائم المقسّمة صفحات)
```

**قواعد التصميم:**
- **الرؤوس:** كل طلب يُرسل `Authorization` و`X-Tenant-Id` (الحضانة المختارة) و`Accept-Language`، فرسائل الأخطاء والملخصات تصل من الخادم بلغة المستخدم.
- **انتهاء الجلسة:** أي `401` على جلسة قائمة يسجّل الخروج تلقائياً.
- **التخزين:** التوكن يُحفظ في التخزين الآمن فقط، ولا يُحفظ أي بيانات أطفال على الجهاز.
- **الصور:** روابطها موقّعة وتنتهي بعد 30 دقيقة، فتُحمَّل مباشرة بلا توكن، والرابط المنتهي يظهر مكانه بديل، والسحب للتحديث يجلب روابط جديدة.
- **الأدوار:** التطبيق لا يقرر الصلاحيات، فقط يُخفي ما لا يخص المستخدم. الخادم هو الحَكَم دائماً.

## الاختبارات

```bash
flutter analyze
flutter test
```

- `test/models_test.dart` يحلّل **استجابات حقيقية** من الخادم في `test/fixtures`. هي مأخوذة من مجموعة Postman التي يولّدها الخادم من استجاباته الفعلية، ولتحديثها بعد تغيير الـ API:
  ```bash
  dart run tool/sync_fixtures.dart ../bahja/docs/api/Bahga-API.postman_collection.json
  ```
- `test/api_client_test.dart` يغطي الرؤوس، والخطأ الموحّد، وانتهاء الجلسة، وانقطاع الشبكة، وجسم طلب النشر.
- `test/app_flow_test.dart` يحاكي رحلات كاملة: دخول وليّة الأمر ورؤية أطفالها، ورسالة خطأ الدخول، والمعلمة تسجّل حضور طفل.

يشغّل CI (`.github/workflows/ci.yml`) التنسيق والتحليل والاختبارات وبناء نسخة الويب مع كل PR.

## الإشعارات الفورية (Push): الخطوة التالية
الخادم جاهز: `POST /v1/me/devices` لتوكن FCM، مع موجّه إشعارات وأولويات وساعات هدوء. لتفعيلها في التطبيق:
1. أنشئ مشروع Firebase، ثم شغّل `flutterfire configure` (يضيف `google-services.json` و`GoogleService-Info.plist`).
2. أضف `firebase_core` و`firebase_messaging`، واطلب الإذن بعد الدخول.
3. أرسل التوكن عبر `AuthRepository.registerDevice` بعد كل دخول وعند `onTokenRefresh`.
4. عند فتح إشعار، استخدم `data.screen` و`data.child_id` للتوجيه، بنفس منطق `InboxScreen`.
